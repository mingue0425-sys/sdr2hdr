# V4.1 Visual Stability Diagnostic

This worktree ports the V4.1 observation path onto production commit
`d97c3d3c8fbf71447ff8b94a7fa7a77c5d25bebf`. It does not alter the promoted V4
values or the production tone expansion arithmetic.

## Production code audit

- V2 is `HDRConfiguration.calibratedV2` with `HDRToneCurveRevision.legacyV2`.
- V4 is `HDRConfiguration.calibratedV4` with `HDRToneCurveRevision.sceneRelativeV4`.
- V4 computes `shoulderStart = 0.68 - 0.20 * contrastStrength`.
- V4 computes `lowMidExpansion = (peakRatio - 1) * strength * 0.08 * lowMidTransition * y`.
- `temporalAdaptation` and scene coordinates are snapshotted in `HDRProcessor` and bound to the same frame. The asynchronous 16x9 estimator updates the next causal frame from its completion handler.
- `sceneShadowFloor` and `sceneShadowTop` are consumed inside the V4 branch of `toneExpand` only when scene statistics are valid. The d97 production estimator remains 16x9 with 16 bins.
- Saturation compensation is applied after tone expansion in linear RGB. The d97 saturation transition uses the fixed configured peak ratio.
- `HDRProcessor` produces the HDRCore EDR texture. `HDRPresentationRenderer` then applies the d97 direct EDR mapper. The mapper leaves luminance at or below `1.0` unchanged and only maps the extended range.
- `processor.update(configuration:)` preserves temporal and scene history while advancing a generation guard so late GPU completions cannot update a newer configuration generation.
- `sourceUnavailable` retains its aggregate counter and now records `NO_NEW_PIXEL_BUFFER`, `COPY_PIXEL_BUFFER_FAILED`, `NO_LAST_FRAME`, `NO_TEXTURE`, `NOT_READY`, and `OTHER` separately.

## Diagnostic path

- `B` switches the live player between `calibrated-v2` and `calibrated-v4` without recreating the player, asset, audio position, or Metal pipelines. The switch is explicitly history-contaminated and is intended for quick inspection.
- `--controlled-ab` creates one V2 and one V4 processor sharing a command queue. Both receive the same pixel buffer and timestamp, while each owns independent temporal and scene state. The active completed texture is selected for presentation.
- `HDRFrameDiagnosticSnapshot` carries frame/timestamp, 64-bin stage percentiles, scene state, temporal sequence, tone-curve contributions, core EDR, presentation EDR, ROI contributions, near-black, and scene-cut diagnostic data.
- DEBUG accumulation is observation-only. The debug shader calls the production `toneExpand` for the output pixel and computes a separate breakdown. Production mode still uses the original causal estimator and non-debug pipeline.
- Shift-drag selects a generic normalized ROI. The same ROI can inspect diffuse skin, another midtone object, hair, clothing, windows, lights, neon, or reflections. No face or skin detector is present.
- `D` prints the current diagnostic. `--diagnostic-json <directory>` enables asynchronous JSON snapshots; normal runs do not create result artifacts.
